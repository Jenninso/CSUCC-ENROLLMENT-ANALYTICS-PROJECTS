Below is a detailed roadmap you can use as your master prompt for developing the system, followed by the system architecture and diagrams.

1. Proposed System

System Title

Visualization of Enrollment Dynamics Utilizing Data Analytics with AI-Driven Decision Support

Main idea

The system will collect historical and current enrollment data and transform it into useful information such as:

Enrollment trends by year/semester

Enrollment by program

Enrollment by year level

Enrollment by gender, if appropriate and legally/ethically permitted

Enrollment by department/college

New vs. returning students

Retention and dropout patterns

Student population growth/decline

Program demand

Enrollment forecasting

Identification of unusual enrollment changes

AI-generated insights

Recommendations for administrators

The important distinction is that the system should not simply display graphs. It should analyze the data and help administrators answer:

"What happened?" → "Why might it be happening?" → "What is likely to happen next?" → "What should we do?"

2. Master Prompt for Building the System

You can give the following prompt to an AI coding assistant and use it as your overall development specification.

MASTER DEVELOPMENT PROMPT

Project Title

Develop a complete web-based information system entitled:

"Visualization of Enrollment Dynamics Utilizing Data Analytics with AI-Driven Decision Support"

Project Objective

Build a secure, user-friendly, responsive, and data-driven enrollment analytics platform that allows educational administrators to monitor historical and current enrollment patterns, visualize enrollment dynamics, perform statistical and predictive analytics, and receive AI-assisted decision support.

The system must transform raw enrollment records into understandable dashboards, analytical reports, forecasts, alerts, and actionable recommendations.

The system should support the following decision-making cycle:

Data → Information → Analytics → Prediction → AI Insight → Recommendation → Decision

11. AI ANALYTICS MODULE

Implement an AI-assisted analytics layer.

The AI should NOT simply generate generic text.

It should receive verified analytical results from the analytics engine.

For example:

Input:

Current enrollment = 4,500

Previous enrollment = 4,850

Growth = -7.2%

BSIT growth = +14%

BSBA growth = -18%

AI output:

"Overall enrollment declined by approximately 7.2%. However, BSIT increased while BSBA declined significantly. Administrators may investigate whether program-specific demand, capacity, scheduling, or recruitment factors contributed to this difference."

The AI should distinguish between:

FACT

Directly supported by data.

TREND

A statistically or visually observable pattern.

FORECAST

A model-generated estimate.

INTERPRETATION

Possible explanation.

RECOMMENDATION

Suggested action.

Never present speculation as fact.

21. AI SAFETY AND GOVERNANCE

The AI must not make autonomous administrative decisions.

It should provide:

"Decision support"

rather than:

"Automatic decision making."

Every AI recommendation should be reviewable by an authorized administrator.

AI responses should include supporting metrics.

The system should avoid statements such as:

"Program X must be closed."

Instead use:

"Program X shows sustained enrollment decline. Administrators may consider reviewing program demand, retention, recruitment, and resource utilization before making any program-level decision."

30. IMPORTANT DEVELOPMENT RULE

Do not build the entire system at once.

Develop incrementally.

First build:

Database → Authentication → Data Import → Dashboard → Analytics → Forecasting → AI → Decision Support

After every phase:

Test it.

Fix errors.

Document it.

Commit the working version.

Continue to the next phase.

Do not implement AI before the underlying data and analytics are reliable.

The AI layer must be based on validated analytical results rather than raw, unverified data.
